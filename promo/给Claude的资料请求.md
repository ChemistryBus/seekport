# 给项目开发 Claude 的资料请求

请基于你参与开发的 SeekPort 项目，输出一份中文“推广制图资料包”，用于让另一个助手制作小红书竖版图文。仓库：https://github.com/ChemistryBus/seekport

不需要写完整营销笔记，不需要预先规定页数或版式。请提供真实项目信息和能用于视觉解释的素材；不知道的写“待作者补充”，不要推测、夸大或补造数据。

## 必需信息

1. **项目定位**：名称及大小写、一句话说明；最适合的用户；他们遇到的具体问题；使用项目后能完成什么。
2. **当前版本与状态**：说明对应的日期、版本或 commit；是否已可公开使用、处于什么阶段。区分“已实现并验证”“已实现但未验证”“规划中”。
3. **最值得展示的功能**：选3—5项即可。每项说明用户做什么、项目返回什么、适用条件或限制；附对应的 README 小节、代码路径或测试记录供制图追溯。不要求为每项新做测试。
4. **一条完整使用示例**：以最有代表性的真实任务，写清输入→关键操作→输出→用户如何使用结果。提供可公开的示例内容；假设数据必须明确标为演示，不混成真实用户案例。
5. **使用门槛与边界**：实际访问/安装方式、支持的平台、是否需要账号或 API key、是否涉及第三方付费、数据存放方式及依赖条件。只写已知现状；不要把开源等同于所有使用成本为零。
6. **项目入口**：准确 GitHub 地址；若有可用演示站、下载页或入门文档，请给准确链接；标注本次建议引导读者执行的动作，可由作者最终选择。

## 有则附上，不必为凑材料制作

- Logo、图标、项目固定配色及已有视觉资产；说明能否用于公开推广。
- 2—4张最能说明功能的清晰真实截图，附文件和说明：属于哪个功能、读者看哪里、是否来自当前版本。优先提供完整原图，标出需要隐藏的信息；不要只给缩小后嵌在文档里的图片。
- 若已有录屏，可给最值得截取的时间点和场景说明。
- 作者明确认可的设计动机、差异特点或开发故事；没有比较证据，不写“首个”“唯一”“最好”等结论。
- 若确实要使用性能、用户量或节省时间等数字，附测量条件、日期和原始结果；没有就不需要。

## 请在末尾列出

- 最建议读者记住的一句话，以及它对应的已实现功能。
- 不适合宣传的内容、仍未完成的功能、容易被误解的限制。
- 必须由作者决定的事项：目标读者、此次最希望获得的行动、是否用个人开发者口吻，以及不愿公开的信息。不要替作者虚构答案。

只提供可公开资料，勿输出密钥、令牌、私人用户数据或未授权第三方素材。请用一份 Markdown 输出，截图等资产单独附文件；这份资料将按原文保留作为制图依据。
